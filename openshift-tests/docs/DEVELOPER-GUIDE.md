# openshift-tests on TNF — Developer Guide

This guide is for people changing or extending the scripts under
`openshift-tests/scripts/`. It explains how the pieces fit together, the
contracts between them, the design decisions behind the odd-looking parts, and
the known rough edges. For how to *use* the scripts see the
[User Guide](USER-GUIDE.md).

Paths are relative to `openshift-tests/` unless stated otherwise.

## 1. Layout

```text
openshift-tests/
├── README.md                 # entry point, links here
├── .gitignore                # runs/, tests-bin/, scripts/debug/, *.log
├── docs/
│   ├── USER-GUIDE.md
│   ├── DEVELOPER-GUIDE.md    # this file
│   └── TNF-AND-CLUSTER.md    # original cluster-access + runbook notes
├── runs/                     # generated: one directory per session (git-ignored)
├── tests-bin/                # generated: extracted openshift-tests binary (git-ignored)
└── scripts/
    ├── test-helpers.sh       # shared library (sourced, never executed)
    ├── extract-tests-binary.sh
    ├── list-tests.sh
    ├── run-suite.sh          # suite runner (batch / interactive / upgrade)
    ├── run-test.sh           # per-test runner (worker for interactive mode)
    ├── run-all-captures.sh   # starts every capture-*.sh, records PIDs
    ├── stop-all-captures.sh
    ├── capture-*.sh          # one collector each
    ├── gather-resource-agent-versions.sh
    ├── check-latest-run.sh
    ├── check-test-result.sh
    ├── summarize-all-runs.sh
    ├── clean-test-runs.sh
    ├── RECOVERY-TESTS-README.md   # original usage notes (superseded by docs/)
    └── debug/                # generated by two collectors (git-ignored, see §7.4)
```

The `SCRATCH_ROOT` variable used throughout resolves to `openshift-tests/`
itself (`"${SCRIPT_DIR}/.."`). The name is a leftover from when these scripts
lived in a `scratch/` directory; some log messages still print `scratch/runs/`.

## 2. Call graph

```text
extract-tests-binary.sh ──▶ tests-bin/openshift-tests
                                  ▲
list-tests.sh ────────────────────┤  (run <suite> --dry-run)
                                  │
run-suite.sh ─────────────────────┤  batch / upgrade: one openshift-tests process per iteration
   │  interactive                 │
   └──▶ run-test.sh ──────────────┘  one openshift-tests process per test (× repeat)
             │
             ├──▶ run-all-captures.sh ──▶ setsid capture-*.sh … (PIDs → capture-pids-<ts>.txt)
             └──▶ stop-all-captures.sh (kill -- -<pgid>, then SIGKILL)

run-suite.sh (recovery, ra-verification) ──▶ gather-resource-agent-versions.sh

check-latest-run.sh / summarize-all-runs.sh / check-test-result.sh ──▶ runs/**/summary.tsv, junit/
clean-test-runs.sh ──▶ rm -rf runs/<session>
```

Two things are deliberately **not** in the graph:

- `run-test.sh` does **not** source `test-helpers.sh`. It carries its own
  copies of `ts`, `log`, `sanitize_name`, `matches_stop_pattern`, the proxy
  loading, and the monitor defaults. Keep the two in sync when you touch either
  (see §9 for the case for merging them).
- `openshift-tests --monitor` is not used by any script. Captures are shell
  processes reading logs from outside the test binary. `run-test.sh` caps
  `OPENSHIFT_TESTS_EXTRA_ARGS` at two `--monitor` occurrences because mass
  monitors have crashed TNF runs.

## 3. Shared library: `test-helpers.sh`

Sourced with `source "${SCRIPT_DIR}/test-helpers.sh"`. If `SCRIPT_DIR` is
already set when it is sourced, it calls `setup_test_directories` immediately,
which exports `SCRATCH_ROOT`, `RUN_DIR` (`runs/`) and `TESTS_BIN_DIR`
(`tests-bin/`) and creates both directories.

| Function | Purpose |
|----------|---------|
| `ts`, `log`, `log_info`, `log_warn`, `log_error` | UTC millisecond timestamp; plain/colored log lines. |
| `sanitize_name STR` | Replace spaces, `/`, `:` and anything outside `[A-Za-z0-9_.-]` with `-`; truncate to 80 chars. Used for run-directory slugs. |
| `setup_test_directories` | See above. Requires `SCRIPT_DIR`. |
| `load_proxy_env` | `source "$PROXY_ENV"` (fails the script if the variable is unset; returns 1 if the file is missing). |
| `setup_hypervisor_config` | Derive `HYPERVISOR_IP` (from `EC2_PUBLIC_IP`), `SSH_USER`, `SSH_KEY_PATH` (with `id_ed25519` fallback) and export `HYPERVISOR_JSON` for `--with-hypervisor-json`. |
| `get_openshift_tests_binary` | Print the first executable among `$OPENSHIFT_TESTS`, `tests-bin/`, `~/.cache/openshift-tests/`. Never extracts. |
| `verify_openshift_tests_binary PATH` | Fail with a search-path listing if the binary is missing. |
| `verify_openshift_tests_version PATH [skip]` | Warn (never fail) if the binary version does not contain the cluster version. Currently unused by the runners; `extract-tests-binary.sh` does its own check. |
| `extract_openshift_tests [DIR]` | Non-interactive extraction via `oc adm release info --image-for=tests` + `oc image extract`. Currently unused; the standalone `extract-tests-binary.sh` is the interactive equivalent with backup/restore. |
| `setup_test_provider` | `TEST_PROVIDER='{"type":"baremetal"}'`, `OPENSHIFT_SKIP_EXTERNAL_TESTS=1`. |
| `setup_monitor_configuration` | Set CI-matching monitor defaults and append to caller-declared `DISABLE_MONITOR_ARGS` / `CLUSTER_STABILITY_ARGS` arrays. |
| `resolve_profile NAME` | Populate `PROFILE_*` variables (§4). Returns 1 and prints the list on an unknown name. |
| `list_profiles` | Human-readable profile table for `--list-profiles`. |
| `matches_stop_pattern TEXT FILE` | Fixed-string search with `rg` or `grep -F`. |

Note that `run-suite.sh` currently sets the monitor defaults inline rather than
calling `setup_monitor_configuration`; both produce the same flags.

## 4. Profiles

A profile is a `case` arm in `resolve_profile` that sets some of:

| Variable | Meaning |
|----------|---------|
| `PROFILE_SUITE` | Suite passed to `openshift-tests run` (and used for discovery unless overridden below). When tests are curated from several suites this must be a superset of all of them, in practice `all`. |
| `PROFILE_FILTER` | Default case-insensitive regex applied to discovered names. Empty = none. |
| `PROFILE_MODE` | `run` (default) or `upgrade` (`openshift-tests run-upgrade`, needs `--to-image`). |
| `PROFILE_DISCOVER_SUITES` | Space-separated suites to `--dry-run` for names. Union is deduplicated, then pinned via `--file` against `PROFILE_SUITE`. Empty = discover from `PROFILE_SUITE`. |
| `PROFILE_EXCLUDE` | Case-insensitive regex of names to drop after the include filter. |
| `PROFILE_GATHER_RA` | `true` to run `gather-resource-agent-versions.sh` after the suite. |

### Adding a profile

1. Add a `case` arm in `resolve_profile` and a line in `list_profiles`
   (`test-helpers.sh`).
2. Verify the suite name once against a real cluster:
   `tests-bin/openshift-tests run <suite> --dry-run | head`.
3. If the profile curates a set (multi-suite or exclusions), run
   `run-suite.sh --profile <name> --list-only` and then a real run: the
   `--file` pre-flight in `run-suite.sh` will tell you if any discovered name
   does not exist in `PROFILE_SUITE`.
4. Update the profile table in `README.md` and `docs/USER-GUIDE.md`.

### Why exclude instead of "run last"

An earlier revision reordered node replacement to the end of the list and
pinned the order via `--file`. That does not work: origin's `--file` honours the
*set* but shuffles the surviving tests with a hard-coded seed
(`cmd_runsuite.go`, seed 42) and exposes no order-preserving flag. The
`ra-verification` profile therefore **excludes** the node-replacement test
(`PROFILE_EXCLUDE="needing manual recovery is replaced"`) so no master is
reprovisioned and both keep the same `resource-agents` build. Interactive mode
does run tests in a deterministic (alphabetical) order because it launches one
process per test.

### `--file` quoting

`openshift-tests --file` reads only double-quoted lines and `strconv.Unquote`s
them before exact matching. Discovery strips the quotes for filtering; the set
file re-adds them with `printf '"%s"\n'`. Bare names silently match nothing and
the run aborts with "no tests to run", which is why `run-suite.sh` does a
`--dry-run` pre-flight with the set file and compares the count before starting.

### `list-tests.sh` and profiles

`list-tests.sh` applies only `PROFILE_SUITE` and `PROFILE_FILTER`. It ignores
`PROFILE_DISCOVER_SUITES` and `PROFILE_EXCLUDE`, so for `ra-verification` it
lists every test in `all`. `run-suite.sh --list-only` is the authoritative
preview. If you extend `list-tests.sh`, reuse the discovery block from
`run-suite.sh` (or move it into the helper library).

## 5. `run-suite.sh` internals

Argument parsing → profile resolution (explicit `--suite`/`--filter` win) →
session name → binary lookup → `load_proxy_env` + `setup_hypervisor_config` →
`setup_test_provider` → one of three paths.

### Upgrade path (`PROFILE_MODE=upgrade`)

Single `openshift-tests run-upgrade "$SUITE" --to-image … --timeout=120m`.
No discovery, no iteration, no `summary.tsv`. Output goes to
`runs/<session>/test/`, captures to `runs/<session>/captures/`.

### Discovery (both remaining paths)

For each suite in `DISCOVER_LIST` (defaults to `[$SUITE]`) run
`openshift-tests run <suite> --dry-run`, keep lines starting with `"`, strip the
quotes. Zero results for any suite aborts (typo protection). Then apply the
include regex, the exclude regex, `sort -u`. `USE_FILE=true` when more than one
discovery suite or an exclude pattern is in play.

### Batch path (default)

One `openshift-tests run "$SUITE"` per iteration, `--max-parallel-tests=1`,
`--timeout=60m`, `-o` raw log, `--junit-dir`. Selector precedence:

1. `USE_FILE` → `--file runs/<session>/test-set.txt` (after the pre-flight).
2. `FILTER == "."` → no selector, whole suite.
3. Otherwise → `--run "$FILTER"`.

`--repeat N` repeats the **suite** N times. Each iteration gets
`iter-NN-<ts>/`, and `summary.tsv` receives one `ALL` row per iteration. Output
is piped through a `while read` loop that prepends a UTC timestamp, so the
`openshift-tests-timestamped.log` timestamps are local receive times, not the
binary's own.

### Interactive path

For each test, optional `[Y/n/q]` prompt, then `run-test.sh --test "$test"
--repeat "$REPEAT" --name "$SESSION_NAME" ±captures`. `run-test.sh` finds the
session directory created earlier that day with the same name and appends to
it (§6). After each test, another `[Y/n/q]` prompt (`n` pauses until Enter).

### Post-run

If `GATHER_RA=true`, call `gather-resource-agent-versions.sh`; its failure is
downgraded to a warning.

## 6. `run-test.sh` internals

Self-contained (see §2). Key points:

- **Suite is hard-coded** to `openshift/two-node`. `--test` values are
  regex-escaped (`sed 's/[]\[^$.*+?{}()|]/\\&/g'`) and passed to `--run`.
- **Single-invocation optimisation.** With `--repeat 1` and more than one
  `--test`, patterns are joined with `|` into one `--run` (origin only honours
  the last `--run`, so they cannot be passed separately). Output goes to
  `iter-01-all-tests-<ts>/` and `summary.tsv` gets one `ALL` row.
  `--stop-on-match` / `--stop-on-fail` are only checked in the loop path.
- **Loop path.** `for iter … for test …`: each run gets
  `iter-NN-test-MM-<ts>-<slug>/`. After each run: stop-on-match (fixed-string
  search of the timestamped log) and stop-on-fail.
- **`test_failed_in_log FOCUS FILE`.** openshift-tests prints one
  `… failed: (<dur>) … "<full name>"` line per failed test. A monitor or
  suite-level failure makes the exit code non-zero but emits no such line, so
  grepping for `failed: (` **and** the focus substring identifies a genuine
  failure of the focused test. This is what makes `--stop-on-fail` robust to
  monitor noise.
- **Session reuse.** `find runs/ -name "<name>-<YYYYMMDD>-*" | sort | tail -1`.
  If found, reuse; else create `<name>-<ts>/`. `summary.tsv` header is written
  only when the file does not exist.
- **`--wait-for-cluster`.** `is_cluster_ready` checks `/healthz`, at least
  `MIN_NODES` Node objects, all `Ready`, and `ClusterVersion` `Available=True`,
  polling every `POLL_SEC` (default 15 min, sized for post-install waits).
- **Logs.** Unlike `run-suite.sh`, output is a plain `tee` into
  `openshift-tests-timestamped.log`: no receive-time prefix is added and no
  `-o` raw log is written. The file name is historical.
- **Captures.** `CAPTURE_LOG_DIR=<run>/captures CAPTURE_TIMESTAMP=<ts>
  run-all-captures.sh`, then `stop-all-captures.sh <pid-file>` after the run.
  The PID file path is derived from the timestamp, so the two must agree.

## 7. Capture framework

### 7.1 Contract for a collector

`run-all-captures.sh` launches each collector as
`setsid <script> [args] >> "${LOG_DIR}/<name>-${TIMESTAMP}.{log,out}" 2>&1 &`
and appends `$!` to `capture-pids-${TIMESTAMP}.txt`. `setsid` puts every
collector in its own process group so `stop-all-captures.sh` can
`kill -- -<pid>` and take down the whole tree (bash + `sleep` + `oc` + `ssh`)
at once, then SIGKILL survivors after two seconds.

A collector must therefore:

1. Read `CAPTURE_LOG_DIR` (default `runs/`) and `CAPTURE_TIMESTAMP` (default
   now) if it writes its own files; or write to stdout and let the launcher
   redirect.
2. `trap 'exit 0' INT TERM` so SIGTERM ends the loop instead of being ignored
   while a foreground child (`sleep`, `ssh`, `oc logs -f`) runs. Collectors that
   fork children keep a `child_pids` array and kill them in an `EXIT` trap.
3. Loop forever and **reconnect**. Every stream you attach to will end during a
   recovery test: nodes reboot, pods are rescheduled, `oc logs -f` on a
   Deployment binds to one pod and never re-attaches. Sleep
   (`*_RECONNECT_SLEEP`, usually 15 s) and re-discover the target.
4. Never let a transient failure exit the script under `set -e`: append
   `|| true` to the streaming command, or use `set -uo pipefail` without `-e`
   as the OVN follow scripts do.
5. Use `BatchMode=yes`, `ConnectTimeout`, and `ServerAliveInterval` on SSH so
   a half-open hop returns control to the loop when a node is killed.

Two patterns to copy:

- **Reconnecting tail over nested SSH** (`capture-pacemaker.sh`,
  `capture-corosync.sh`): resolve the master IP from `virsh net-dhcp-leases
  <VIRSH_LEASE_NETWORK>` on the hypervisor every iteration (a rebooted node may
  get a new lease), honour `MASTER_{0,1}_IP` overrides, write `=== connected /
  disconnected / IP changed ===` markers into the log.
- **Pod-discovery fan-out** (`capture-ceo.sh`, `capture-fencing-job.sh`): poll
  `oc get pods -l …` every `*_POLL_SEC`, start one `oc logs -f --timestamps`
  per pod never seen before (keyed in an associative array), one output file
  per pod. `capture-ceo.sh` also grabs `--previous` on first sight so an
  in-place crash is not lost.

### 7.2 Adding a collector

1. Create `scripts/capture-<thing>.sh` following §7.1. Start with a header
   comment listing prerequisites, env knobs, and output file names; that
   header is the collector's documentation.
2. Add a numbered block in `run-all-captures.sh`: guard on what it needs
   (`KUBECONFIG`, a deployment existing), launch with `setsid`, append the PID,
   echo the output path and any tunables.
3. Run `shellcheck scripts/capture-<thing>.sh`.
4. Validate standalone for a minute against a live cluster, then
   `run-all-captures.sh` + `stop-all-captures.sh` and confirm no orphans:
   `pgrep -af capture-`.
5. Add a row to the table in `docs/USER-GUIDE.md` §7 and the header comment
   of `run-all-captures.sh`.

### 7.3 Ordering and numbering

The comment numbers in `run-all-captures.sh` (`# 1)` … `# 10)`, with `4b)`
and duplicated `5)`/`6)`/`7)`) reflect insertion history, not launch order.
They are harmless but renumber them if you restructure the file.

### 7.4 Known inconsistency: `scripts/debug/`

`capture-virsh-status.sh` and `capture-baremetal-operator.sh` hard-code
`LOG_DIR="${SCRIPT_DIR}/debug"` and ignore `CAPTURE_LOG_DIR`. Their `.log`
files land in `scripts/debug/` (hence the `.gitignore` entry), while the
launcher's redirect of their stdout goes to `<run>/captures/<name>-<ts>.out`.
`capture-pacemaker.sh` and `capture-corosync.sh` default to the same directory
but honour `CAPTURE_LOG_DIR`, so they are fine when launched by a runner.

The fix is a one-line change in each of the two scripts:

```bash
LOG_DIR="${CAPTURE_LOG_DIR:-${SCRIPT_DIR}/debug}"
```

After that, the launcher's line for `virsh` can drop the `.out` redirect or
keep it for console messages; either way the run directory becomes
self-contained.

## 8. Result helpers

- `summary.tsv` is the contract between runners and readers. Columns:
  `iter`, `test_index` (`1..N` or `ALL`), `result` (`PASS` or `FAIL(<rc>)`),
  `run_dir` (absolute), `focus` (test name or a description). Tab-separated,
  one header line.
- `check-latest-run.sh` picks the newest `openshift-two-node-suite-*` session by
  name sort, prints `summary.tsv`, counts `PASS`/`FAIL(` rows, and falls back
  to scanning `iter-*-test-*/test/junit/*.xml` for `failures="…"` when the
  summary is missing.
- `summarize-all-runs.sh` does the same over every `openshift-two-node-suite-*`
  session and computes an overall pass rate, stripping `[sig-…]`,
  `[OCPFeatureGate:…]`, `[Suite:…]` prefixes from failed names.
- `check-test-result.sh <run-dir>` is a plain `ls` + `tail -50` + junit grep.

**Known limitation.** The `openshift-two-node-suite-*` glob only matches
sessions created by `run-suite.sh` without `--profile`. Profile runs are named
`<profile>-suite-*` and `run-test.sh` sessions default to `tnf-two-node-*`.
Replace the glob with `-name '*'` (all session directories contain
`summary.tsv` or nothing), or accept a pattern argument, and both readers
cover every runner. Upgrade sessions have no `summary.tsv` and are correctly
skipped by the `continue` in `summarize-all-runs.sh`.

## 9. Conventions

- **Shebang** `#!/usr/bin/bash` (not `/bin/bash`), set in the "she-bang line
  fixes" commit. Keep it for new scripts.
- **Strict mode** `set -euo pipefail` for runners and helpers. Long-running
  collectors that must survive transient command failures use
  `set -uo pipefail` and handle errors explicitly.
- **ShellCheck clean.** Where a directive is needed, prefer a targeted
  `# shellcheck disable=SCxxxx` with a comment explaining why (see the
  `SC2206` intentional word-split in `run-suite.sh` and `SC2016` in
  `capture-ovn-chassis-trace.sh`).
- **No personal paths.** Anything site-specific comes from `PROXY_ENV` or an
  override variable with a documented default; required variables use
  `${VAR:?message}` so the failure names the variable.
- **Timestamps** are UTC. `ts` prints milliseconds; file-name timestamps are
  `YYYYmmdd-HHMMSS`. A capture bug fixed on this branch came from mixing UTC
  and local time in file names, so do not reintroduce `date` without `-u` for
  anything that is later matched by name.
- **Markdown** must pass `npx markdownlint-cli2 '**/*.md'` from the repo root
  (`MD013` line length is disabled; tables and headings are checked).
- **Help text.** Every user-facing script answers `-h`/`--help` with a
  heredoc. Update it together with the docs when you add a flag.

## 10. Testing a change

There is no unit-test harness; the scripts are exercised against a live
cluster. A minimal pass before pushing:

```bash
cd openshift-tests
shellcheck scripts/*.sh
npx markdownlint-cli2 '**/*.md'                      # from repo root

export PROXY_ENV=<…>/proxy.env
scripts/list-tests.sh --profile recovery              # discovery + binary lookup
scripts/run-suite.sh --profile ra-verification --list-only   # multi-suite discovery + exclude
OVN_CHASSIS_ONCE=1 scripts/capture-ovn-chassis-trace.sh      # SSH + API + SB connectivity
scripts/run-all-captures.sh && sleep 30 && scripts/stop-all-captures.sh
pgrep -af 'capture-' || echo "no orphans"
scripts/run-test.sh --test "recovery restore quorum" --no-captures --name dev-check
```

For anything touching `--file` handling, also run a real
`run-suite.sh --profile ra-verification` and confirm the pre-flight passes and
the run executes the expected count.

## 11. Backlog and rough edges

Collected while writing these docs. None block use; they are listed so the next
person does not rediscover them.

| Area | Issue | Suggested fix |
|------|-------|---------------|
| Result readers | `check-latest-run.sh` / `summarize-all-runs.sh` only match `openshift-two-node-suite-*` (§8). | Widen the glob or add a pattern argument. |
| Captures | `capture-virsh-status.sh` and `capture-baremetal-operator.sh` ignore `CAPTURE_LOG_DIR` (§7.4). | One-line default change in each. |
| `list-tests.sh` | Ignores `PROFILE_DISCOVER_SUITES` / `PROFILE_EXCLUDE`. | Share the discovery block with `run-suite.sh` via `test-helpers.sh`. |
| `run-test.sh` | Duplicates helper functions instead of sourcing `test-helpers.sh`; only two-tier binary lookup. | Source the library; keep the `test_failed_in_log` helper local or move it too. |
| `run-test.sh` | `--stop-on-match` / `--stop-on-fail` silently unused in the single-invocation path. | Either evaluate them after the combined run or warn when they are set with `--repeat 1` and multiple tests. |
| Defaults | Captures default **on** in `run-test.sh` and **off** in `run-suite.sh`. | Pick one; document either way. |
| Messages | `run-suite.sh` prints `Results in: scratch/runs/…`; several headers still say `scratch/`. | Replace with `runs/`. |
| Timeouts | `run-suite.sh` hard-codes `60m` (batch) and `120m` (upgrade); `run-test.sh` has `--timeout`. | Add `--timeout` to `run-suite.sh` and pass it through. |
| `run-all-captures.sh` | Prints `virsh … -> <LOG_DIR>/virsh-<ts>.log` although that file is written under `scripts/debug/`. | Resolved by the §7.4 fix. |
| `capture-ovn-chassis-trace.sh` | Exits if master IPs cannot be resolved at start, unlike the pacemaker/corosync collectors which retry. | Adopt the retry-in-loop pattern. |
| Session reuse | Same-day reuse in `run-test.sh` is keyed only on `--name`; unrelated runs can merge. | Have `run-suite.sh` pass an explicit `--session-dir` instead of relying on the day-prefix lookup. |

## 12. History

The branch was built up in this order, which explains the shape of the code:

1. **Generalized test helpers** — `test-helpers.sh`, profiles, `run-suite.sh`
   / `list-tests.sh` replacing one-off scripts (`list-recovery-tests.sh`,
   `run-dualreplica-tests.sh`, `run-node-replacement-test-3x.sh`, …).
2. **Capture signal handling** — collectors ignored SIGTERM and accumulated
   across soak iterations; fixed with `trap 'exit 0' INT TERM` and
   process-group kills.
3. **Capture stop path / timestamp fixes** — `stop-all-captures.sh` accepts a
   full PID-file path; UTC vs local-time mismatch in file names fixed.
4. **`--stop-on-fail`** — focused-test failure detection that ignores
   monitor-only failures.
5. **Hardening captures** — reconnect loops for every `oc logs -f` stream,
   CEO all-incarnations capture, machine-api snapshot, fencing/update-setup
   job monitors.
6. **ShellCheck fixes**, **shebang fixes**, and a first attempt at forcing
   node replacement last via `--file` ordering.
7. **Zero-test protection** — replaced "run last" with `PROFILE_EXCLUDE`
   (origin shuffles `--file` sets), added multi-suite discovery, the `--file`
   pre-flight, the zero-tests abort, and the `PATCHED_RA_MARKER` verdict in
   `gather-resource-agent-versions.sh`.
